01这份 SOP 怎么用

这是用 Claude 一步步搭看板的指南，每个阶段告诉你：

  • 这一步要做什么（清楚目标）
  • 给 AI 的提示词长什么样（直接抄）
  • AI 会输出什么（你能预期）
  • 怎么验证它做对了（眼睛能看、手能点）
不需要技术背景

非技术运营 / 产品也能跟着做。难点在把自己想要的东西讲清楚给 AI，不在写代码 — 写代码的事 AI 全包。

02准备工具

2.1 选一个 AI 工具

选项说明
Claude Code（最强）在终端跑，能直接帮你建文件、跑命令、调试。官网
Claude.ai（网页）对话式，你复制粘贴代码。门槛低，但效率比 Code 低
ChatGPT、Gemini 等类似 Claude.ai，按个人偏好

这份 SOP 默认用 Claude Code（推荐），其他 AI 思路一样。

2.2 还需要

  • 一台 Mac（Windows / Linux 也行，命令略有差异）
  • GitHub 账号（免费注册）
  • 你公司后台的访问权限（账号 + 密码 + 那个会变的验证码的密钥）
  • 能上你公司内网（如果 admin 在内网。Lite 版要求 Mac 在公司网）

2.3 给 AI 看 SOP 自己

⌘ 开场提示词
我想给公司搭一个商业看板（数据来自公司 admin 后台）。 我打算按这份 SOP 走：https://eightnrcn2025-create.github.io/commercial-dashboard-2026-05/sop-lite-mac.html 我是非技术背景，需要你带着我走。每一步告诉我： 1. 这一步要干嘛 2. 我需要给你什么信息 3. 你会做什么 4. 我怎么验证你做对了 我们从阶段 1 开始。

03阶段 1：调研后台

🎯 目标：摸清后台有哪些报表、能取哪些指标

3.1 你要做的（人工部分）

  1. 登 admin 后台
  2. 把所有可能用得上的页面都点一遍，截图保存
  3. 记下每个报表能筛选什么（日期 / 渠道 / 游戏...）和能导出多少行

3.2 让 AI 帮你梳理

⌘ 提示词
我把 admin 后台几个核心报表截图给你看。 你帮我整理出： 1. 每个报表的字段有哪些 2. 每个字段是"已经有"还是"要派生算" 3. 哪些字段对"商业化看板"最关键 4. 输出成一个表格，列：指标 / 后台位置 / 是否已有 / 取数说明 / 优先级（P0/P1/P2） 我先发第一张截图：[截图]

3.3 AI 会输出

一个 CSV 或表格，把你截图里的字段都对齐到指标。你跟需求方对一遍，决定哪些进看板。

验证：阶段 1 完成的标志
你手里有一份"指标 → 后台位置"映射表，30-50 项 P0/P1 指标。

04阶段 2：设计指标体系

🎯 目标：决定看板要分几个 tab，每个 tab 看什么

4.1 给 AI 你的指标表

⌘ 提示词
基于刚才那份指标表，帮我设计看板的 tab 结构。 要求： - 老板 30 秒能看懂的"总览大盘"放第一个 tab - 分维度（游戏 / 渠道 / 套餐...）每个一个 tab - 时间趋势单独一个 tab - 留存 / LTV 这种深度指标可以合并 输出每个 tab 的：标题 / 核心 KPI 卡 / 主要图表 / 表格列。

4.2 你跟 AI 来回调整

  • "网游 tab 加 ARPU 列"
  • "渠道 tab 太挤，把 ARPPU 挪到 tooltip 里"
  • "留存周期改成 D1/D3/D7/D14/D30 五档"

05阶段 3：写抓取脚本

🎯 目标：让程序自动登录后台、把报表数据抓下来、生成一个数据文件

5.1 重点：先搞清楚你的后台是怎么登录的

后台登录常见有三种"关卡"组合，你先自己登一遍，看是哪种：

  1. 只有一个网页登录表单（填用户名密码就进）
  2. 先弹一个浏览器自带的小框（让你输用户名密码），过了之后才是网页登录表单
  3. 上面任意一种，再加一个每隔几十秒就变的 6 位验证码（谷歌验证器那种）

怎么判断：

  • 打开后台网址，最先弹出来的是浏览器自带的"输用户名密码"小框？ → 属于第 2 种
  • 过了之后看到的是你后台自己的登录页 → 有网页登录表单
  • 登录时还要填一个会变的验证码 → 带验证码那种

5.2 给 AI 提示词

⌘ 提示词
帮我写一个脚本，让它每次运行就自动做这几件事： 1. 登录我的后台（网址是 xxxx）。登录有三关：先弹一个系统的"输用户名密码"小框 → 再填网页上的登录表单 → 最后填一个每隔几十秒就变的 6 位验证码。 2. 按顺序打开这几个报表页面，把里面的数据抓下来：[报表 1 网址] [报表 2 网址] … 3. 把数据存成一个数据文件；每次只把新增的并进去，老数据保留、不要覆盖。 几点说明： - 这些报表是打开后才慢慢加载出来的，请用"能等它真正加载完再抓"的办法，别用只读网页源码的简单抓取。 - 那个会变的验证码，让脚本自己算，别让我每次手输。 - 账号密码不要写死在代码里，单独存一个文件让脚本读。 账号密码我自己保管（存系统钥匙串或单独文件里），不会贴给你。

5.3 AI 会做的几件事

  1. 问你每个报表的网址（不知道？让它教你怎么找）
  2. 把那个抓数据的脚本写出来
  3. 给你一个填账号密码的模板，让你把密码填进去
  4. 帮你把运行需要的环境和工具都装好
  5. 先跑一次，让你确认结果对不对
坑预警

第一次跑大概率会失败 — 后台防抓取、超时、验证码对不上、抓错了位置……都正常。把报错原样发给 AI，让它来修，一般来回 2-3 次就能搞定。

验证：阶段 3 完成的标志
脚本跑完后，会生成一个新的数据文件 → 你打开它，能看到熟悉的数字（跟你后台里看到的对得上）。

06阶段 4：看板前端

🎯 目标：把抓到的数据变成一个能点、能看的看板

6.1 给 AI 提示词

⌘ 提示词
帮我把上一步抓到的数据做成一个看板网页。 要求： - 用现成的图表库画图（你来选合适的），别用复杂的前端框架；做成一个打开就能看的单页网页。 - 风格走"给老板看的高管范儿"：深海军蓝配暗金，干净利落。 - 数据直接用上一步生成的那个数据文件，别让我手动改。 页面按阶段 2 设计的 tab 来分：[tab 1] [tab 2] … 每个 tab 都要能： 1. 切时间区间（近 7 天 / 近 30 天 / 自己选起止） 2. 两个时期对比（本期 vs 上一期） 3. 表格点列头能排序 每做完一个 tab，给我看一眼截图。

6.2 反复调整

  • "柱图改成横向"
  • "日期选择器默认显示前一天"
  • "tooltip 加上 ARPU"
  • "颜色太花，统一成 3-4 个色调"
验证：阶段 4 完成的标志
在浏览器里打开你的看板 → 所有 tab 和数据都能正常显示。

07阶段 5：发布到 GitHub Pages

🎯 目标：让团队所有人能用浏览器看

7.1 让 AI 帮你建仓库 + 推

⌘ 提示词
帮我把当前这个文件夹发布成一个网页，让团队用浏览器就能打开看： 1. 在 GitHub 上建一个新项目（名字叫 commercial-dashboard，公开的就行） 2. 把我这个文件夹整个传上去 3. 打开 GitHub 自带的网页托管（GitHub Pages） 4. 弄好后，把看板的网址直接发给我 GitHub 我已经登录好了，你直接用命令帮我弄，别让我一步步手点。

7.2 把不该上传的排除

⌘ 提示词
帮我设置好"哪些文件不要传到 GitHub"——尤其是存账号密码的那个文件，千万别传上去；还有那些临时文件、运行日志，也都不用传。
验证：阶段 5 完成的标志
上一步 AI 会直接把你看板的网址发给你。点开它，看板能正常显示就行。然后把这个网址转给同事，他们也能打开看。

08阶段 6：Mac 上设定时

🎯 目标：脚本每 30 分钟自动跑，数据持续更新

8.1 让 AI 帮你设置自动定时

⌘ 提示词
帮我把那个抓数据的脚本设成"每 30 分钟自动跑一次"（用 Mac 自带的定时功能就行）。 要求： - Mac 一开机就自动启动，不用我手动开 - 每次跑完自动把新数据上传（这样看板就会自动更新） - 留一份运行记录，方便出问题时排查 - 给我一个一键安装的小脚本，我运行一下就装好 我的项目就放在当前这个文件夹里。

8.2 让自动上传不用每次输密码

AI 会教你两种办法，让脚本每次自动上传时不用你手动输密码：

  1. 用 GitHub 官方工具登录一次（最简单）
  2. 配一把"免密钥匙"
验证：阶段 6 完成的标志
  • 能查到那个定时任务已经在后台跑着
  • 过 30 分钟，去 GitHub 项目里看一眼，会自动多出一条"数据更新"的记录
  • 刷新看板页面 → 顶部的时间戳变成"刚刚更新"

09团队使用 / 边界明确

9.1 发给团队的话

团队使用说明（直接抄给同事）

看板地址：[贴上 AI 给你的看板网址]

  1. 每天打开看就行，不用登录
  2. 看 header 时间戳是绿色（< 1 小时）/ 黄色（4 小时+）/ 红色（1 天+）
  3. 看到红色 → 找你们自己的开发人员

9.2 Lite 版的边界

⚠️ 这些情况下数据不会更新
  • 你 Mac 关机（合盖睡眠 OK，关机不行）
  • 你 Mac 不在公司网（出差不接 VPN）
  • 后台改了密码 / 重置了那个验证码

如果团队反馈"数据卡了"，先检查这三条。

9.3 团队点"刷新"按钮会怎样？

Lite 版的"刷新"按钮只是把页面重新加载一下，拿网上当前最新的那份数据。它不会让程序重新去后台抓一遍。

如果想要"点刷新就立刻去抓最新数据"，得升级到 Pro 版（加一台服务器）。

10关键经验

10.1 怎么和 AI 高效对话

  • 先讲背景再讲需求。"我在做 xxx 项目，遇到 yyy 问题" 比 "怎么 yyy" 好 10 倍
  • 报错原样发。不要意会 — 报错有时候 AI 能从一个不起眼的字眼看出真因
  • "你这步为啥这样做" — 不懂就问，AI 会解释，你下次就知道
  • 不满意就直说 — "这个 UI 太花" / "这步太复杂能不能简化"，AI 是工具不是同事，不用客气

10.2 必须人工把关的环节

  • 账号密码、那个会变的验证码的密钥，不要发到 AI 对话框里（让 AI 用"隐藏输入"或系统钥匙串的方式，让你自己输进去）
  • 每次上传之前，瞄一眼要传的内容，确认没把存密码的那个文件也一起传上去

10.3 卡住了怎么办

  1. 把全部上下文发给 AI：你做了什么、看到什么、期望是什么
  2. 如果 AI 也卡住，让它给你 3 个不同的尝试方向，你挑一个继续
  3. 真不行 → 把整套上下文发到 Stack Overflow / Reddit / 群里求助
最后一句

非技术背景搭这个系统的最大风险，不是不会写代码，而是不清楚自己要什么。把指标体系想清楚（阶段 1+2），后面 AI 会带着你走。
