01系统概览

本系统是一个 商业化指标可视化看板，给团队（包括非技术同事）通过浏览器即时查看公司商业化数据。

整体定位：

  • 数据源：公司后台 admin1866（内网 .line.ccc 域名）
  • 数据获取：用 Playwright headless Chrome 自动登录 + 抓表（绕过手动 admin 操作）
  • 数据存储：JS 文件 data.js 在 GitHub 公开仓库里
  • 展示：单页 HTML + ECharts，托管在 GitHub Pages
  • 更新机制：VPS cron + 用户点刷新 双触发，VPS runner + Mac runner 双承载

核心指标：8 个总览 KPI、自由区间对比、30 天趋势图、单游戏 TOP / 单机 TOP / 套餐 / 渠道 / LTV / 留存 共 7 个 tab。数据范围回溯到 2025-09-01（约 9 个月历史，自动归档不丢失）。

02整体架构

团队任何人浏览器 ↓ 打开看板 URL / 点"刷新"按钮 ↓ [Cloudflare Worker] （持有 GITHUB_PAT secret， 前端代码里不出现 PAT） ↓ POST [GitHub Actions API] workflow_dispatch / cron 触发 ↙ ↘ [Mac runner] [VPS runner ← 主力] (备份, Mac 开机时) (24×7 在线) ↘ ↙ update_data.py （Playwright 登录 admin1866 → 抓 13 张报表 → 合并归档 → 生成 data.js） ↓ git push (用 GITHUB_TOKEN env) ↓ GitHub Pages 重建（约 50 秒） ↓ 团队网页拿到新数据

04日常使用

团队（包括非技术同事）

推荐用法

把看板 URL 加入浏览器收藏夹，每天打开。

  1. 看 header 时间戳：🟢绿 = 数据新；🟡黄 = 数据 4 小时+ 没更新；🔴红 = 一天+ 没更新
  2. 点右上"刷新"按钮 → 强制触发远程拉取最新数据（约 2-3 分钟，按钮显示进度）
  3. 7 个 tab 切换看不同维度：总览 / 30 天趋势 / 网游 / 单机 / 套餐 / 渠道 / LTV·留存
  4. 总览里有"自由区间对比"，可以自己选两段日期对比

你（eight，作为维护者）

正常情况下不需要做任何事 — 系统全自动。需要你介入的时机：

  • 数据 header 显示 🔴 红色（一天没更新）
  • 团队反馈"刷新不出新数据" 且确认 GitHub 上 data.js 也没更新
  • 需要新增指标 / 调整看板布局
  • admin1866 密码 / 2FA 重置

06故障排查

症状 ➜ 数据 N 天没更新（header 红色）

  1. 看 GitHub Actions 页面，最近 run 是 success 还是 failed
  2. 如果都是 failed，点进去看 logs，常见原因：
    • 登录失败 → admin1866 改了密码或 2FA 重置：见 §7.1 更新凭证
    • ERR_EMPTY_RESPONSE → admin1866 临时挂掉或限流；等 30 分钟再看（脚本已经有 6 次重试）
    • git push 失败 → workflow GITHUB_TOKEN 权限被改：见 §6.3
  3. 如果 GitHub Actions 没有 run（连触发都没）：检查 VPS cron（§5.7）和 runner 状态（§5.2）

症状 ➜ runner 都 offline

VPS runner：ssh root@76.13.220.93 && cd /opt/actions-runner && ./svc.sh start

Mac runner：cd ~/actions-runner && ./svc.sh start

如果 svc.sh 不工作，可能是 service 被 unload 了，重新装：./svc.sh install root && ./svc.sh start（Mac 上不要带 root）

症状 ➜ Worker 返回 500 / 401

多半是 Worker 的 GITHUB_PAT 过期或被 revoke：

  1. 生成新 fine-grained PAT（GitHub Settings → Developer settings → Fine-grained tokens；Permissions: Actions = Read and write）
  2. 命令行更新 Worker Secret：
cd /Users/laoba/commercial-dashboard
wrangler secret put GITHUB_PAT
# 提示 "Enter a secret value:" 时粘贴新 PAT，回车

症状 ➜ Pages 重建特别慢（超过 5 分钟）

GitHub 那边偶尔抽风。耐心等，或去 Actions 页面看 pages build and deployment workflow 的状态。

症状 ➜ 团队反馈"看板挂了"但你自己打开正常

大概率是他们浏览器缓存。让他们：

  • 右上角点"刷新"按钮（带强制 cache-bust）
  • 或 Chrome: Cmd+Shift+R 强制刷新
  • 实在不行清浏览器缓存

07凭证管理

安全原则
  • 所有密码 / token 从不明文进 git 仓库（GitHub 有 secret scanning，会拒绝 push）
  • Mac 上的 secrets：macOS Keychain + .env 文件（chmod 600，已 gitignored）
  • VPS 上的 secrets：/opt/commercial-dashboard/.env（chmod 600）
  • Worker 上的 secret：Cloudflare 自带的加密 Secret 系统

08修改 / 扩展

8.1 加一个新指标到看板

  1. 判断这个指标在 admin1866 的哪个页面（查 商业化看板指标-精简版.csv 的"后台位置"列）
  2. 如果脚本已经抓那张表 → 看是不是已经在 data.js 输出（可能只是前端没用上）
  3. 如果是新表：在 update_data.py 的 REPORT_URLS dict 加路径，main() 里加 fetch_report 调用，加 aggregator 函数
  4. 在 index.html 加一个 KPI 卡 / chart 容器
  5. 在 app.js 写渲染逻辑
  6. commit + push，VPS 下次跑就会出数

8.2 改更新频率

变更 VPS cron：

ssh root@76.13.220.93
crontab -e
# 改 */30 (每 30 分钟) 为 */15 / */10 / */5 等

变更 Mac launchd：编辑 com.eight.dashboard-update.plist 里的 StartInterval（秒数）然后：

launchctl unload ~/Library/LaunchAgents/com.eight.dashboard-update.plist
cp /Users/laoba/commercial-dashboard/com.eight.dashboard-update.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.eight.dashboard-update.plist
注意

频率太高（< 5 分钟）会给 admin1866 服务器压力 + 频繁触发 Pages 重建。30 分钟是建议下限。

8.3 加新维度数据（比如更长历史 / 单游戏每日趋势）

修改 update_data.py 里 EARLIEST（默认 2025-09-01）或 d30（默认 30 天）的常量。

注意 data.js 文件大小会增长，太大（> 3MB）会影响团队加载速度。

8.4 给团队成员开 GitHub 协作权限（看 Actions 日志）

GitHub repo → Settings → Collaborators → Add people → 输入对方 GitHub 用户名

09应急 / 重建

9.1 整套 VPS 挂了，要从零重建

步骤（在新 Ubuntu VPS 上 root 登录）：

  1. SCP 把 .env 文件传到新 VPS 的 /root/.env
  2. 跑一键安装脚本：
curl -sSL https://raw.githubusercontent.com/eightnrcn2025-create/commercial-dashboard-2026-05/main/setup_runner_linux.sh -o /tmp/setup.sh
bash /tmp/setup.sh
  1. 会问 RUNNER TOKEN（去 repo Settings → Actions → Runners → New self-hosted runner 拿）
  2. 装完加 cron：
(crontab -l 2>/dev/null; echo "*/30 * * * * curl -sS -X POST https://dashboard-refresh.eight-nrcn-2025.workers.dev/dispatch > /dev/null") | crontab -

9.2 Mac 换新机器

同样思路：

  1. 装 Python 3 + git（macOS 自带）+ Node.js
  2. git clone https://github.com/eightnrcn2025-create/commercial-dashboard-2026-05.git /Users/<new-user>/commercial-dashboard
  3. 复制旧 Mac 的 .env 文件到新位置（或重跑 migrate_secrets.py）
  4. 跑 ./setup.sh 装 venv + playwright + chromium
  5. 跑 ./run.sh 测试一次
  6. 装 launchd（./install_cron.sh）
  7. 装 Mac runner（./setup_runner.sh <token>）

9.3 Cloudflare Worker 整个挂了

cd /Users/laoba/commercial-dashboard
wrangler deploy
wrangler secret put GITHUB_PAT  # 重新设

9.4 GitHub repo 误删 / 历史搞乱了

本地 Mac 和 VPS 都有完整代码。新建 GitHub repo，

cd /Users/laoba/commercial-dashboard
git remote set-url origin https://github.com/<new-org>/<new-repo>.git
git push -u origin main --force

然后改 cloudflare-worker.js 里的 REPO 字符串、config.js 里的 WORKER_URL（不变）、Pages 开启。
