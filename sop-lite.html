01这份 SOP 怎么用

这是用 Claude 一步步搭看板的指南，每个阶段告诉你：

  • 这一步要做什么（清楚目标）
  • 给 AI 的提示词长什么样（直接抄）
  • AI 会输出什么（你能预期）
  • 怎么验证它做对了（眼睛能看、手能点）
不需要技术背景

非技术运营 / 产品也能跟着做。难点在把自己想要的东西讲清楚给 AI，不在写代码 — 写代码的事 AI 全包。

02准备工具

2.1 选一个 AI 工具

选项说明
Claude Code（最强）在终端跑，能直接帮你建文件、跑命令、调试。官网
Claude.ai（网页）对话式，你复制粘贴代码。门槛低，但效率比 Code 低
ChatGPT、Gemini 等类似 Claude.ai，按个人偏好

这份 SOP 默认用 Claude Code（推荐），其他 AI 思路一样。

2.2 还需要

  • 一台 Mac（Windows / Linux 也行，命令略有差异）
  • GitHub 账号（免费注册）
  • 你公司 admin 后台的访问（账号 + 密码 + 2FA 密钥）
  • 能上你公司内网（如果 admin 在内网。Lite 版要求 Mac 在公司网）

2.3 给 AI 看 SOP 自己

⌘ 开场提示词
我想给公司搭一个商业看板（数据来自公司 admin 后台）。 我打算按这份 SOP 走：https://eightnrcn2025-create.github.io/commercial-dashboard-2026-05/sop-lite.html 我是非技术背景，需要你带着我走。每一步告诉我： 1. 这一步要干嘛 2. 我需要给你什么信息 3. 你会做什么 4. 我怎么验证你做对了 我们从阶段 1 开始。

03阶段 1：调研后台

🎯 目标：摸清后台有哪些报表、能取哪些指标

3.1 你要做的（人工部分）

  1. 登 admin 后台
  2. 把所有可能用得上的页面都点一遍，截图保存
  3. 记下每个报表能筛选什么（日期 / 渠道 / 游戏...）和能导出多少行

3.2 让 AI 帮你梳理

⌘ 提示词
我把 admin 后台几个核心报表截图给你看。 你帮我整理出： 1. 每个报表的字段有哪些 2. 每个字段是"已经有"还是"要派生算" 3. 哪些字段对"商业化看板"最关键 4. 输出成一个表格，列：指标 / 后台位置 / 是否已有 / 取数说明 / 优先级（P0/P1/P2） 我先发第一张截图：[截图]

3.3 AI 会输出

一个 CSV 或表格，把你截图里的字段都对齐到指标。你跟需求方对一遍，决定哪些进看板。

验证：阶段 1 完成的标志
你手里有一份"指标 → 后台位置"映射表，30-50 项 P0/P1 指标。

04阶段 2：设计指标体系

🎯 目标：决定看板要分几个 tab，每个 tab 看什么

4.1 给 AI 你的指标表

⌘ 提示词
基于刚才那份指标表，帮我设计看板的 tab 结构。 要求： - 老板 30 秒能看懂的"总览大盘"放第一个 tab - 分维度（游戏 / 渠道 / 套餐...）每个一个 tab - 时间趋势单独一个 tab - 留存 / LTV 这种深度指标可以合并 输出每个 tab 的：标题 / 核心 KPI 卡 / 主要图表 / 表格列。

4.2 你跟 AI 来回调整

  • "网游 tab 加 ARPU 列"
  • "渠道 tab 太挤，把 ARPPU 挪到 tooltip 里"
  • "留存周期改成 D1/D3/D7/D14/D30 五档"
验证：阶段 2 完成的标志
你能用 1 张纸画出 6-8 个 tab 的草图（什么位置放什么图）。

05阶段 3：写抓取脚本

🎯 目标：让 Python 脚本自动登录 admin、抓表、生成数据文件

5.1 重点：先告诉 AI admin 的登录方式

常见三种组合，你测一下用的是哪种：

  1. 只有表单登录
  2. nginx Basic Auth（系统弹框）+ 表单
  3. 上面任一 + Google Authenticator 2FA

怎么测：

  • 访问 admin URL，第一个弹的是系统级输用户名密码框？ → 有 Basic Auth
  • 过了后看到自己的登录页 → 表单登录
  • 表单里有"谷歌验证码"字段 → 有 2FA

5.2 给 AI 提示词

⌘ 提示词
帮我写一个 Python 脚本 update_data.py，每次跑： 1. 登录 admin（URL 是 xxxx） 认证方式：[nginx Basic Auth + 表单登录 + Google Authenticator] 2. 依次抓这些报表的数据：[报表 1 URL] [报表 2 URL] ... 3. 把数据合并归档到一个 data.js 文件 data.js 格式：const DAILY = [...]; const WANGYOU = [...]; 要求： - 用 Playwright（不是 BeautifulSoup，因为表格异步加载） - TOTP 用 pyotp 库自动算 - 密码不要硬编码，从 .env 文件读 - 加增量归档逻辑：data.js 里旧数据保留，新数据 merge 进去 我先把账号密码用 macOS Keychain 或 .env 文件存。

5.3 AI 会做的几件事

  1. 问你各报表的 URL（不知道？让它教你怎么扒）
  2. 写出 update_data.py
  3. 给你一份 .env 模板，让你填密码
  4. 帮你装 venv + playwright + chromium
  5. 跑一次让你验证
坑预警

第一次跑大概率会失败 — admin 的反爬、超时、TOTP 错位、表格 selector 不对……都正常。把报错原样发给 AI，它来 debug，2-3 轮一般能修好。

验证：阶段 3 完成的标志
python update_data.py 跑完 → 生成一个新的 data.js → 你打开它能看到熟悉的数字（跟你 admin 里看的对得上）。

06阶段 4：看板前端

🎯 目标：把 data.js 渲染成可互动看板

6.1 给 AI 提示词

⌘ 提示词
帮我写一个看板前端，3 个文件：index.html + app.js + data.js（data.js 已有，是上一步生成的）。 技术： - 用 ECharts 画图 - 不要任何框架（不要 React / Vue）— 单文件 HTML 直接打开就能跑 - 视觉风格："执行级"，深海军蓝 header + 暗金 accent tab 结构按之前阶段 2 设计的来： [tab 1] [tab 2] ... 每个 tab 都要支持： 1. 时间区间切换（近 7 天 / 近 30 天 / 自定义） 2. 数据对比（本期 vs 对比期） 3. 表格列可点击排序 写完每个 tab 给我看一下截图。

6.2 反复调整

  • "柱图改成横向"
  • "日期选择器默认显示前一天"
  • "tooltip 加上 ARPU"
  • "颜色太花，统一成 3-4 个色调"
验证：阶段 4 完成的标志
用浏览器双击 index.html → 看板能正常显示所有 tab 和数据。

07阶段 5：发布到 GitHub Pages

🎯 目标：让团队所有人能用浏览器看
注意

GitHub Pages 免费托管 = 仓库要 public = 数据公开。决定之前跟需求方对齐：

  • 商业指标接受公开 → 用免费方案
  • 不能接受 → 用 GitHub Pro（30/月可开私有 Pages）或 Cloudflare Pages + Access

7.1 让 AI 帮你建仓库 + 推

⌘ 提示词
帮我： 1. 在 GitHub 建一个新的 public 仓库（名字 commercial-dashboard） 2. 把当前文件夹推上去（用 gh CLI，不要让我手动登录） 3. 开 GitHub Pages（main 分支根目录） 4. 给我那个 Pages URL 我电脑上 gh CLI 已经登录了（我先跑过 gh auth login）。

7.2 把不该上传的排除

⌘ 提示词
建 .gitignore，排除： - .env（密码文件） - .venv/（Python 环境） - logs/（日志） - __pycache__/
验证：阶段 5 完成的标志
浏览器打开 https://<你 GH 用户名>.github.io/<仓库名>/ → 看板正常显示。把这个 URL 发给同事，他们也能看。

08阶段 6：Mac 上设定时

🎯 目标：脚本每 30 分钟自动跑，数据持续更新

8.1 让 AI 设 macOS launchd

⌘ 提示词
帮我设置 macOS launchd，让 update_data.py 每 30 分钟自动跑一次。 要求： - Mac 开机自动启动 - 跑完自动 git push 到 GitHub（这样 Pages 自动更新） - 日志写到 logs/stderr.log 方便排错 - 提供 install_cron.sh 脚本，我直接跑就装好 我的项目路径：/Users/xxx/commercial-dashboard

8.2 让 git push 不需要每次手动输密码

AI 会教你两种方式：

  1. 用 GitHub CLI 的认证（最简单）
  2. 配 SSH key
验证：阶段 6 完成的标志
  • launchctl list | grep dashboard 能看到任务在
  • 看 GitHub 仓库的 commit 历史 → 30 分钟后能看到 "auto: 数据更新" 的新 commit
  • 浏览器刷新看板 → header 时间戳变成"刚刚更新"

09团队使用 / 边界明确

9.1 发给团队的话

团队使用说明（直接抄给同事）

看板地址：https://<你的 Pages URL>

  1. 每天打开看就行，不用登录
  2. 看 header 时间戳是绿色（< 1 小时）/ 黄色（4 小时+）/ 红色（1 天+）
  3. 看到红色 → 找 eight

9.2 Lite 版的边界

⚠️ 这些情况下数据不会更新
  • 你 Mac 关机（合盖睡眠 OK，关机不行）
  • 你 Mac 不在公司网（出差不接 VPN）
  • admin 后台改了密码 / 重置了 2FA

如果团队反馈"数据卡了"，先检查这三条。

9.3 团队点"刷新"按钮会怎样？

Lite 版的"刷新"按钮只是重新加载页面，拿 GitHub Pages 上当前最新的 data.js。不会触发新一轮抓取。

如果想要"点刷新立刻拉新数据"，要升级到 Pro 版（加 VPS）。

10关键经验

10.1 怎么和 AI 高效对话

  • 先讲背景再讲需求。"我在做 xxx 项目，遇到 yyy 问题" 比 "怎么 yyy" 好 10 倍
  • 报错原样发。不要意会 — 报错有时候 AI 能从一个不起眼的字眼看出真因
  • "你这步为啥这样做" — 不懂就问，AI 会解释，你下次就知道
  • 不满意就直说 — "这个 UI 太花" / "这步太复杂能不能简化"，AI 是工具不是同事，不用客气

10.2 必须人工把关的环节

  • 密码 / TOTP 密钥不要发到 AI 对话框（让 AI 用 read -s 或 keychain 命令交互式提示你输入）
  • git push 之前看 commit 内容，确认没把 .env 推上去
  • 第一次开 GitHub Pages 时，仓库一定是 public — 确认这里数据敏感度可接受

10.3 卡住了怎么办

  1. 把全部上下文发给 AI：你做了什么、看到什么、期望是什么
  2. 如果 AI 也卡住，让它给你 3 个不同的尝试方向，你挑一个继续
  3. 真不行 → 把整套上下文发到 Stack Overflow / Reddit / 群里求助
最后一句

非技术背景搭这个系统的最大风险，不是不会写代码，而是不清楚自己要什么。把指标体系想清楚（阶段 1+2），后面 AI 会带着你走。
