01这份 SOP 怎么用

这是用 Claude 一步步搭看板的指南，Pro 版多两个阶段把可用性拉满：

  • 阶段 1-8 都是问 AI 即可
  • 每个阶段都告诉你：要做啥 / 给 AI 啥提示词 / AI 输出啥 / 怎么验证
  • Pro 版前 6 个阶段跟 Lite 版 一样，阶段 7+8 是 Pro 独有（VPS + Cloudflare Worker）
什么时候用 Pro 版
  • 团队 ≥ 3 人，希望随时点刷新就能拿新数据（即使你 Mac 关机）
  • 老板可能晚上 10 点想看一眼今天的数
  • 你出差不带电脑也想让团队照常用
  • 愿意花 5-10 美元/月养一台 VPS

04阶段 2：设计指标体系

🎯 目标：决定看板要分几个 tab，每个看什么
⌘ 提示词
基于刚才的指标表，帮我设计看板的 tab 结构。 要求： - 老板 30 秒能看懂的"总览大盘"放第一个 - 分维度（游戏/渠道/套餐...）每个一个 tab - 时间趋势单独一个 tab - 留存 / LTV 这种深度指标可合并 输出：每个 tab 的标题 / 核心 KPI 卡 / 主要图表 / 表格列。

05阶段 3：写抓取脚本

🎯 目标：脚本自动登录 admin、抓表、生成 data.js

5.1 先弄清楚 admin 的登录方式

常见三层组合：

  1. 只表单
  2. nginx Basic Auth（系统弹框）+ 表单
  3. + Google Authenticator 2FA

5.2 提示词

⌘ 提示词
帮我写 update_data.py： 1. 登录 admin（URL 是 xxxx） 认证方式：[nginx Basic Auth + 表单登录 + Google Authenticator] 2. 依次抓这些报表：[报表 URL 1] [报表 URL 2] ... 3. 数据合并归档到 data.js 格式：const DAILY = [...]; const WANGYOU = [...]; 要求： - Playwright（不要 BeautifulSoup） - TOTP 用 pyotp 自动算 - 密码从 .env 读，不硬编码 - 增量归档：旧数据保留，新数据 merge 密码我用 .env 文件存（chmod 600）。
坑预警
第一次大概率失败 — admin 反爬、超时、selector 不对……正常。报错原样发 AI，2-3 轮能修好。
验证
python update_data.py → 生成新 data.js → 里面的数字跟你 admin 里看的对得上。

07+阶段 7：VPS 24×7 跑 Pro 独有

🎯 目标：让 Mac 关机时也能自动更新

7.1 先验证一个关键问题

VPS 必须能上你公司的 admin 后台

如果你公司 admin 在内网，VPS（公网）通常访问不了。先 SSH 到 VPS 跑：

curl -I --max-time 5 http://<你的 admin URL>
  • 返回 401 = ✅ 能上，继续
  • 返回 Could not resolve host = ❌ 不行，换方案

不行怎么办：

  • 选项 A：找公司内一台 24×7 的机器装 runner（最稳）
  • 选项 B：让 IT 配 VPN / Cloudflare Tunnel（要 IT 配合）
  • 选项 C：放弃 VPS 路线，回 Lite 版

7.2 买一台便宜 VPS

推荐 Hostinger 最便宜的 KVM 套餐（约 5 美元/月），或类似的。系统选 Ubuntu 22.04 / 24.04。

7.3 让 AI 装 runner

⌘ 提示词
我有一台 Ubuntu VPS（IP 是 x.x.x.x，root 可登录），帮我装上： 1. Python 3 + venv 2. Playwright + Chromium（含系统依赖） 3. 把 commercial-dashboard 仓库 clone 到 /opt/ 4. 注册为 GitHub Actions self-hosted runner（你帮我去 GitHub 设置页面拿 token，或告诉我去哪点） 写一个一键安装脚本 setup_runner_linux.sh，scp 上去跑一次就行。 我先把 .env 文件 scp 到 VPS。

7.4 给 VPS 加 cron 让它每 30 分钟自己触发

⌘ 提示词
VPS 上加一个 cron entry，每 30 分钟触发一次 workflow。 （workflow 触发方法看下一步 Cloudflare Worker）
验证
  • GitHub 上 Settings → Actions → Runners 能看到 VPS 在线
  • VPS 上 ./svc.sh status 显示 running
  • 等 30 分钟，看 GitHub 仓库 commit 历史有新的 "auto: 数据更新"

08+阶段 8：Cloudflare Worker 远程触发 Pro 独有

🎯 目标：团队点"刷新"按钮能立刻拉新数据（不等 30 分钟）

8.1 思路

团队浏览器 → Cloudflare Worker（小代理，免费）→ GitHub Actions API → VPS runner 跑 → push → Pages 重建。

[团队浏览器] ↓ POST [Cloudflare Worker]（持有 GitHub PAT） ↓ POST + PAT [GitHub Actions] ↓ [你 VPS 上的 runner 跑脚本] ↓ push [Pages 重建] ≈ 2-3 分钟后团队看到新数据

8.2 为什么不能直接前端 → GitHub？

GitHub API 需要 PAT 认证，PAT 不能放前端代码（GitHub 自动检测就拦下 push 了）。所以中间加一个 Worker 当代理：

  • PAT 存在 Worker 的加密 Secret 里
  • 前端只调 Worker URL（公开的，没问题）
  • Worker 拿 PAT 去调 GitHub API

8.3 让 AI 全程带你做

⌘ 提示词
帮我搭 GitHub Actions 远程触发链路： 1. 写一个 .github/workflows/refresh.yml - 触发：workflow_dispatch - 在 self-hosted runner 上跑 update_data.py - 用 GITHUB_TOKEN env 自动 push（绕开本地 git credential） 2. 写一个 Cloudflare Worker（cloudflare-worker.js） - POST /dispatch → 触发 workflow - GET /status → 返回最新 run 的状态 - PAT 从 env.GITHUB_PAT 读 3. 帮我用 wrangler CLI 部署 Worker： - 我已经装好了 wrangler 并 wrangler login 过 - 给我一个 wrangler.toml 配置文件 - 帮我 wrangler deploy 4. 教我去 GitHub 生成 fine-grained PAT（actions: Read and write） - 拿到 PAT 后用 wrangler secret put GITHUB_PAT 存进 Worker（隐藏输入） 5. 改前端的"刷新"按钮： - 之前只是 reload 页面 - 改成调 Worker /dispatch 触发 workflow - 轮询 /status 直到完成，再 reload
坑预警
Cloudflare 新版 UI 默认建"Workers + Static Assets"型 Worker — 这种不能加 Secret。用 wrangler 命令行部署，是纯 Worker 不会有这问题。
验证
  1. 命令行 curl -X POST https://<你的 Worker URL>/dispatch → 返回 HTTP 200 "OK"
  2. GitHub Actions 页面看到一个新 run 在跑
  3. 约 2-3 分钟后 Pages 拿到新数据
  4. 团队在网页点"刷新"按钮 → 走相同链路

09团队使用

9.1 发给团队的话

团队使用说明（直接抄给同事）

看板地址：https://<你的 Pages URL>

  1. 每天打开看就行
  2. 右上角"刷新"按钮 = 强制拉一次最新数据（2-3 分钟）
  3. 看 header 时间戳：🟢绿 = 新；🟡黄 = 4 小时+；🔴红 = 1 天+
  4. 看到红色或刷新没反应 → 找 eight

9.2 Pro 版的可用性

✅ 永远可用
  • 你 Mac 关机 = OK，VPS 顶着
  • 你出差不带电脑 = OK
  • 团队晚上点刷新 = OK

9.3 还是会有问题的情况

  • admin 后台改密码 / 重置 2FA → 你要更新 VPS 上的 .env
  • VPS 本身挂了 → Hostinger 面板能看到，重启或换机器
  • admin1866 长期挂掉 → 不归你管

10关键经验

10.1 怎么和 AI 高效对话

  • 先讲背景再讲需求。"我在做 xxx，遇到 yyy" 比单问 "yyy" 好 10 倍
  • 报错原样发，不要意会
  • 不懂就问"为啥"，AI 会解释
  • 不满意直说，AI 是工具不是同事

10.2 必须人工把关的环节

  • 密码 / PAT / TOTP 密钥不要发到 AI 对话 — 让 AI 用 wrangler secret put 或 read -s 之类交互输入
  • git push 前看 commit 内容，确认没把 .env 推上去
  • GitHub Pages 公开 / 私有 选择前跟需求方对齐

10.3 Pro 版额外的运维操作

场景怎么处理
VPS 挂了 / 升级系统Hostinger 面板重启；重大变化让 AI 重跑一次安装脚本
admin 密码变了SSH 到 VPS，nano /opt/commercial-dashboard/.env 改对应行
PAT 过期了新建 PAT；wrangler secret put GITHUB_PAT 替换
团队反馈刷新没反应看 GitHub Actions 页面有没有 run；runner 是否在线
最后一句

Pro 版比 Lite 版多 1-2 倍组件，但稳定性和可用性是另一个量级。如果是给团队真用、给老板看，Pro 版的额外投入值。
