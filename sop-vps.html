01这份 SOP 怎么用

这是用 Claude 一步步搭看板的指南，Pro 版多两个阶段把可用性拉满：

  • 阶段 1-8 都是问 AI 即可
  • 每个阶段都告诉你：要做啥 / 给 AI 啥提示词 / AI 输出啥 / 怎么验证
  • Pro 版前 6 个阶段跟 Lite 版 一样，阶段 7+8 是 Pro 独有（多一台一直开着的服务器 + 一个让团队远程刷新的小中转）
什么时候用 Pro 版
  • 团队 ≥ 3 人，希望随时点刷新就能拿新数据（即使你 Mac 关机）
  • 老板可能晚上 10 点想看一眼今天的数
  • 你出差不带电脑也想让团队照常用
  • 愿意花 5-10 美元/月养一台云服务器

3.2 让 AI 梳理

⌘ 提示词
我把 admin 后台几个核心报表截图给你。 帮我整理出： 1. 每个报表的字段 2. 每个字段是"已有"还是"要派生算" 3. 哪些字段对商业化看板最关键 4. 表格：指标 / 后台位置 / 是否已有 / 取数说明 / 优先级（P0/P1/P2） 第一张截图：[截图]
验证
手里有一份"指标 → 后台位置"映射表，30-50 项 P0/P1 指标。

04阶段 2：设计指标体系

🎯 目标：决定看板要分几个 tab，每个看什么
⌘ 提示词
基于刚才的指标表，帮我设计看板的 tab 结构。 要求： - 老板 30 秒能看懂的"总览大盘"放第一个 - 分维度（游戏/渠道/套餐...）每个一个 tab - 时间趋势单独一个 tab - 留存 / LTV 这种深度指标可合并 输出：每个 tab 的标题 / 核心 KPI 卡 / 主要图表 / 表格列。
验证
能用 1 张纸画出 6-8 个 tab 的草图。

05阶段 3：写抓取脚本

🎯 目标：让程序自动登录后台、把报表数据抓下来、生成一个数据文件

5.1 先搞清楚你的后台是怎么登录的

常见有三种"关卡"组合：

  1. 只有一个网页登录表单
  2. 先弹一个浏览器自带的小框（输用户名密码），过了才是网页登录表单
  3. 上面任意一种，再加一个每隔几十秒就变的 6 位验证码

5.2 提示词

⌘ 提示词
帮我写一个脚本，让它每次运行就自动做这几件事： 1. 登录我的后台（网址是 xxxx）。登录有三关：先弹一个系统的"输用户名密码"小框 → 再填网页上的登录表单 → 最后填一个每隔几十秒就变的 6 位验证码。 2. 按顺序打开这几个报表页面，把里面的数据抓下来：[报表 1 网址] [报表 2 网址] … 3. 把数据存成一个数据文件；每次只把新增的并进去，老数据保留、不要覆盖。 几点说明： - 这些报表是打开后才慢慢加载出来的，请用"能等它真正加载完再抓"的办法，别用只读网页源码的简单抓取。 - 那个会变的验证码，让脚本自己算，别让我每次手输。 - 账号密码不要写死在代码里，单独存一个文件让脚本读。 账号密码我自己保管（存在一个单独的、只有我能读的文件里），不会贴给你。
坑预警
第一次大概率失败 — 后台防抓取、超时、抓错了位置……都正常。报错原样发给 AI 让它修，一般 2-3 次就好。
验证
脚本跑完后会生成一个新的数据文件 → 里面的数字跟你后台里看到的对得上。

06阶段 4：看板前端

🎯 目标：把抓到的数据变成一个能点、能看的看板
⌘ 提示词
帮我把上一步抓到的数据做成一个看板网页。 要求： - 用现成的图表库画图（你来选合适的），别用复杂的前端框架；做成一个打开就能看的单页网页。 - 风格走"给老板看的高管范儿"：深海军蓝配暗金，干净利落。 - 数据直接用上一步生成的那个数据文件。 页面按阶段 2 设计的 tab 来分。 每个 tab 都要能： 1. 切时间区间（近 7 天 / 近 30 天 / 自己选起止） 2. 两个时期对比（本期 vs 上一期） 3. 表格点列头能排序
验证
在浏览器里打开你的看板 → 所有 tab 和数据都能正常显示。

07+阶段 7：服务器 24×7 跑 Pro 独有

🎯 目标：让 Mac 关机时也能自动更新

7.1 先验证一个关键问题

服务器必须能访问到你公司的后台

如果你公司后台在内网（只有公司网络能进），那台云服务器在公网，通常访问不了。让 AI 带你登上服务器，跑一句测试命令，看能不能连上你的后台网址：

curl -I --max-time 5 http://<你的后台网址>
  • 返回一串带 401 的结果 = ✅ 能连上，继续
  • 返回"找不到主机"之类的 = ❌ 连不上，得换方案

连不上怎么办：

  • 方案 A：在公司内部找一台一直开着的电脑来当这台"服务器"（最稳）
  • 方案 B：让公司 IT 帮你把网络打通（需要 IT 配合）
  • 方案 C：放弃服务器这条路，回 Lite 版

7.2 买一台便宜的云服务器

推荐 Hostinger 最便宜的套餐（约 5 美元/月），或类似的服务商。系统（操作系统）选 Ubuntu 就行。

7.3 让 AI 帮你把服务器配好

⌘ 提示词
我有一台云服务器（Ubuntu 系统，IP 是 x.x.x.x，能用管理员账号登录）。帮我在上面把"自动抓数据"需要的东西都装好，让它以后能自动跑那个抓取脚本： 1. 装好运行脚本需要的程序和工具（具体装什么你来定） 2. 把我的项目下载到这台服务器上 3. 把它接上 GitHub，让 GitHub 能指挥这台服务器自动跑（如果要去 GitHub 拿个授权码，带我一步步弄） 最好给我一个"一键安装"的脚本，我传上服务器跑一次就装好。 存账号密码的那个文件我会自己传到服务器上，不会贴给你。

7.4 让服务器每 30 分钟自己触发一次

⌘ 提示词
在这台服务器上设一个定时，让它每 30 分钟自动触发一次更新。 （具体怎么触发，看下一步的"远程刷新"设置。）
验证
  • 在 GitHub 的设置页里，能看到你这台服务器显示"在线"
  • 在服务器上查一下，那个后台服务显示"正在运行"
  • 等 30 分钟，去 GitHub 项目里看一眼，会自动多出一条"数据更新"的记录

08+阶段 8：让团队能一键远程刷新 Pro 独有

🎯 目标：团队点"刷新"按钮能立刻拉新数据（不等 30 分钟）

8.1 思路

团队点"刷新" → 一个免费的小中转服务 → 通知 GitHub → 你的服务器跑一遍抓取 → 上传 → 网页自动更新。整条链路大概是这样：

[团队浏览器，点"刷新"] ↓ [免费的小中转服务]（替你保管"授权钥匙"） ↓ [GitHub] ↓ [你的服务器跑一遍抓取脚本] ↓ 上传 [网页自动更新] ≈ 2-3 分钟后团队看到新数据

8.2 为什么要绕这一圈，不能网页直接连 GitHub？

因为通知 GitHub 需要一把"授权钥匙"，而这把钥匙绝不能放进网页代码里（任何人都能看到网页代码，钥匙一暴露就危险）。所以中间加一个小中转服务来替你保管钥匙：

  • 钥匙安全地存在中转服务里，外人看不到
  • 网页只跟这个中转服务打交道（它是公开的，没关系）
  • 由中转服务拿着钥匙去通知 GitHub

8.3 让 AI 全程带你做

⌘ 提示词
我想做一个"团队点一下刷新按钮，就能远程让服务器重新抓一次数据"的功能。帮我全程搭好： 1. 在 GitHub 上设置好"一键就能让服务器跑一次抓取"的自动流程。 2. 做一个小的中转服务（用 Cloudflare 的免费服务，相当于一个安全的中间人）： - 收到"刷新"请求 → 就去通知 GitHub 跑一次 - 也能查一下"这次跑完了没" 3. 帮我把这个中转服务部署上线（要用的工具我已经装好、也登录过了，你直接用命令帮我弄）。 4. 带我去 GitHub 生成一把"授权钥匙"（只给它够用的最小权限），再把这把钥匙安全地存进中转服务里。注意：这把钥匙不能写进网页代码、也不要贴给你，存的时候是隐藏输入的。 5. 把网页上那个"刷新"按钮改一下： - 以前点了只是刷新一下页面 - 改成点了就触发上面这套流程，然后等它跑完，再自动刷出新数据。
坑预警
在 Cloudflare 网页上手动建这个中转服务，有一种类型存不了"授权钥匙"，容易踩坑。让 AI 用命令行帮你部署就不会有这个问题——记得提醒 AI 走命令行这条路。
验证
  1. 让 AI 帮你测一下那个中转服务，能正常收到"刷新"请求并回应成功
  2. 去 GitHub 项目里看，有一个新任务正在跑
  3. 约 2-3 分钟后，网页上能看到新数据
  4. 最后团队在网页上点"刷新"按钮 → 走的是同一条链路，能成功

09团队使用

9.1 发给团队的话

团队使用说明（直接抄给同事）

看板地址：[贴上 AI 给你的看板网址]

  1. 每天打开看就行
  2. 右上角"刷新"按钮 = 强制拉一次最新数据（2-3 分钟）
  3. 看 header 时间戳：🟢绿 = 新；🟡黄 = 4 小时+；🔴红 = 1 天+
  4. 看到红色或刷新没反应 → 找你们自己的开发人员

9.2 Pro 版的可用性

✅ 永远可用
  • 你 Mac 关机 = OK，服务器顶着
  • 你出差不带电脑 = OK
  • 团队晚上点刷新 = OK

9.3 还是会有问题的情况

  • 后台改了密码 / 重置了那个验证码 → 你要去服务器上把保存的账号密码更新一下
  • 服务器本身挂了 → 在服务商面板里能看到，重启或换一台
  • 你们公司后台长期挂掉 → 那不归你管

10关键经验

10.1 怎么和 AI 高效对话

  • 先讲背景再讲需求。"我在做 xxx，遇到 yyy" 比单问 "yyy" 好 10 倍
  • 报错原样发，不要意会
  • 不懂就问"为啥"，AI 会解释
  • 不满意直说，AI 是工具不是同事

10.2 必须人工把关的环节

  • 账号密码、授权钥匙、那个会变的验证码的密钥，都不要发到 AI 对话框里 — 让 AI 用"隐藏输入"的方式，让你自己输进去
  • 每次上传之前，瞄一眼要传的内容，确认没把存密码的那个文件也一起传上去

10.3 Pro 版额外的运维操作

场景怎么处理
服务器挂了 / 要升级系统在服务商面板里重启；变化大的话，让 AI 重跑一次安装脚本
后台密码变了让 AI 带你登上服务器，把保存账号密码的那个文件里对应的改掉
授权钥匙过期了重新生成一把；让 AI 帮你把中转服务里的旧钥匙换成新的
团队反馈刷新没反应去 GitHub 项目里看任务有没有在跑；那台服务器是否在线
最后一句

Pro 版比 Lite 版多 1-2 倍组件，但稳定性和可用性是另一个量级。如果是给团队真用、给老板看，Pro 版的额外投入值。
